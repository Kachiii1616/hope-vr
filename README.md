# HOPE しごとタウン（職業体験 VR の下書き）

> **まだ下書きです。** hope-work（就労支援アセスメントアプリ）の下書き `vr-draft/` から移しました。
> hope-work とはまだつながっておらず、記録はブラウザの中だけに残ります。

手描きの地図「Work Island」をもとにした島を見わたし、地域ごとにある、その土地らしい仕事のお店に入って体験します。
体験の結果は、hope-work の「② 作業体験」と同じ項目（配慮なし／配慮あり・完成数・不良・声かけ・質問・時間）で残します。

## 動かし方

- パソコン・スマホ: `index.html` をブラウザで開く。ドラッグで見回し、タップでえらぶ。下の帯から直接お店へも行ける。
- VR（Meta Quest など）: https で配信したページを、ヘッドセットのブラウザで開いて「VR で入る」。
  コントローラーで指して、トリガーでえらぶ。
  - GitHub Pages を使うなら: Settings → Pages → Source を「Deploy from a branch」、Branch を `main` / `/ (root)` にする。
    `https://kachiii1616.github.io/hope-vr/` で開ける（WebXR は https が必須）。
- 外から読むライブラリは three.js（r128, cdnjs）とフォント（Google Fonts）だけ。ビルド不要の 1 ファイル。

## 島の構成（Work Island）

上が北。最初は島の南の上空（見わたし台）から全体を見て、旗かお店をえらぶと、そのお店の前へ移動します。

```
            ビーチ     林業エリア            漁村
          海の家    （ジップライン）  山        ～～ 入り江 ～～
            首都              （夏山登山・冬スキー）   漁港
   住宅地        学校エリア
 繁華街   湖                                農村
        IT企業（準備中）
```

| 地域 | お店 | 仕事 | 進め方 | 見ている力（不良の基準） |
| --- | --- | --- | --- | --- |
| 漁港 | 物流センター | ピッキング | 注文票の品を順不同でひろう | 指示の読みとり（ちがう品をひろう） |
| 繁華街 | コンビニ | 品出し | 持っている品を正しい棚へ | 分類（ちがう棚に置く） |
| 海の家 | 清掃 | テーブルふき | よごれをぜんぶふく。もようはふかない | 見分け・やり残しの確認 |
| 繁華街 | カフェ | ドリンクづくり | レシピの順番どおり（3 種類） | 手順の記憶・順序 |
| 住宅地 | 介護施設 | 配膳の手伝い | 食事の形 → 名札の順 | 2 つの条件の照合 |

| 農村 | 農園 | トマトの収穫 | 赤いものだけとる | 見分け |
| 学校エリア | 作業所 | お守りづくり | ふくろ → 中紙 → ひも → 検品かご | hope-work の作業マスタ（お守り作成）と同じ題材 |

### 繁華街の場所

地図で描いた位置（首都の南西・住宅地と湖のあいだ）を中心にしています。
人が住む場所（住宅地）、働く場所（首都の役所・IT 企業）、島の目抜き通り（漁港 → 山の南 → 学校 → 首都 → 繁華街）が
ここで集まるので、人の流れがいちばん多くなる場所として、高いビルと看板をこの通りぞいに集めています。

### 地図の扱い

`index.html` の `ISLAND`（海岸線）・`SITES`（お店の場所と向き）・`ROADS`（道）は、手描きの地図を 960×830 の方眼（px）に写した座標です。
1 px = 0.12 m（島は東西およそ 100 m）。お店を動かすときは `SITES` の座標を変えれば、木や建物は空いている場所に自動でよけて置かれます。

### 1 回の体験の流れ

1. お店の前に来る → 仕事の説明。「配慮なし」「配慮あり」をえらぶ。
2. 5 個つくる（5 回）。
3. 結果を掲示板に出し、「きろく」に残す。

### 配慮なし／配慮あり のちがい

hope-work の `SUPPORT_METHODS` の言い方にそろえています。

| | 配慮なし | 配慮あり |
| --- | --- | --- |
| 指示 | 短い一言だけ（例:「テーブルの よごれを ふく」） | 数や中身まで（例:「よごれを ぜんぶ ふく（4か所）」） |
| 手順 | 出さない | チェックリスト形式で、いまの手順を色で示す |
| ガイド | なし | 8 秒手が止まると、つぎに選ぶものが光る（声かけ 1 回として数える） |
| 読み上げ | なし | 指示・つぎの手順を読み上げる |
| 目標数 | 出さない | 「できた 2 / 5」 |

「ヒント」ボタンはどちらでも押せて、押した回数は「本人からの質問」として数えます。

### 記録の形

`TrialPhase`（`app/src/domain/types.ts`）と同じ名前の項目で残します。「きろく」→「JSON をコピー」で取り出せます。

```json
{
  "jobId": "cafe", "taskName": "カフェ（ドリンクづくり）", "category": "実務",
  "phase": {
    "label": "VR 体験（配慮あり）", "withSupport": true,
    "supports": ["チェックリスト形式の手順書", "説明を一つずつ小分けにする", "治具・ガイドを使う", "目標数を伝える"],
    "durationSec": 184, "completed": 5, "inspected": 5, "defects": 2,
    "promptCount": 1, "questionCount": 0, "observation": ""
  }
}
```

## 穴と、決めること（優先順の案）

1. **記録をどこに入れるか（いちばん大事）。** いまはブラウザの中だけ。hope-work の作業体験
   （`work-trials`）に「場面」として足すのか、VR 専用の記録を別に持つのかを決める。
   足すなら利用者 ID（UUID）と作業マスタ ID・版が要る。VR の中で利用者を選ぶ画面か、
   職員がタブレットで「いまから VR」と開始する仕組みが必要。
2. **VR の結果を、実際の作業と同じ重さで扱わない。** VR はつかみ・力加減・立ち仕事の
   体力が見えない。記録では「VR 体験」と分かるラベルを付けたままにし、結果シートでは
   「関心・手順理解の目安」に留める。
3. **酔い・不安への配慮。** いまはお店の間を 0.7 秒で移動する（`prefers-reduced-motion` なら瞬間移動）。
   VR では瞬間移動＋暗転のほうが酔いにくい。1 回 5〜10 分で区切る、すぐ外せる案内も要る。
4. **職業のえらび方。** いまの 8 つは手元の題材で作った仮。地域の A 型・B 型・一般就労先の
   実際の仕事（求人・実習先）から選び直すと、就労選択支援の「比べた選択肢」に使える。
5. **作業マスタとつなぐ。** `round()` の中身を、hope-work の作業マスタ（手順・不良基準・目標数）から
   作れるようにすると、事業所ごとに職業を増やせる。
6. **見た目。** 道具は箱や円柱の仮の形。写真や 3D モデルに差し替えると、実物との結びつきが強くなる。

## これから作り込むとき

- 職業を足すときは `JOBS` に 1 つ足すだけ（お店は円に自動で並ぶ）。
- テストから動かすための入口として `window.hopeTown`（`goBooth` / `startSession` / `select`）を出している。
- 本格的に作るなら、three.js を npm で入れ（いまの r128 → 最新）、WebXR の `VRButton` と
  コントローラーモデルを使う形に直す。
